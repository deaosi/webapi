API 地址

OpenAI 兼容接口

地址来自当前浏览器访问的服务地址。调用时在 Authorization 中使用 Bearer 调用密钥。

本网关原生仅 Chat 协议（聊天/模型）。Responses（Codex）与 Anthropic Messages（Claude Code）由三协议适配层提供，同一把调用密钥通用：Anthropic 客户端可用 Bearer 或 x-api-key 鉴权。

三协议地址（适配层）

Chat / Responses / Messages

Anthropic 客户端把 Base URL 填到三协议地址（去掉末尾 /v1），模型填 cn:xxx；适配层无状态，不支持 Responses 的 previous_response_id（传完整 input 代替）。

调用密钥

管理密钥在配置页设置；此处创建的是调用密钥。完整调用密钥仅在创建成功时显示一次。

「调用」统计该密钥发起过的聊天请求次数（含失败重试），「最近调用」为最近一次使用时间（含模型列表查询）。

上游渠道

启用渠道隔离

渠道 = 一个账号分组 + 该组的上游属性（上游域 / 模型白名单 / 启停）。 成员账号在账号池页的「分组」列指定；绑定了分组的密钥只能用同组账号， 组内无可用即返回错误，不会借用其他分组的账号。未绑定分组的密钥不受限制。

生效路径说明：渠道分组只在经过网关鉴权（`withAPIAuth`）能看到调用密钥 ID 的入口生效， 即直连 panel 的 /v1/*（公网经 Caddy 的同路径亦可）。/adapter/v1/* 目前把上游身份统一换成主密钥， 绑定在该路径上视同未绑定——这是已知限制，跨路径透传调用密钥需要单独的鉴权改造。

渠道定义 渠道 = 一个账号分组 + 它的上游属性与路由权重；成员账号在「账号池」页归组

渠道类型上游地址模型白名单优先级权重成员状态操作

密钥分组绑定 每个调用密钥走弹窗绑定一个渠道分组；解绑即全池可用

密钥名称密钥前缀绑定渠道分组实际生效

白名单留空 = 不限模型；支持 glm-5* 这样的前缀通配。上游域留空 = 不限， 填 cn/global 时该密钥只能走对应域（显式写错域的模型名会被拒绝）。
